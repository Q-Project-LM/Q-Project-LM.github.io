Архитектуру выбрали абляцией

Вместо того чтобы сразу брать нашу тернарную Q-архитектуру, мы обучили три кандидата одного размера на одинаковых данных (0.5 млрд токенов, одно расписание) и сравнили loss на отложенных данных:

ВариантLoss (EN / RU-edu / RU-wiki)Среднее
A — архитектура Q-164M (тернарные веса, замороженный словарь-отпечаток)2.92 / 3.29 / 2.983.06
B — мини-Qwen3.8-Flash-Next2.52 / 2.83 / 2.502.62
C — B + тернарные веса + словарь-отпечатокна 0.2 хуже B на каждой точке, остановлен досрочно

B выиграл с большим отрывом и стал архитектурой всей линейки. Тернарные веса на таком размере стоят слишком дорого по качеству.

Архитектура

  • 8 слоёв: три слоя Gated DeltaNet (линейное внимание с рекуррентным состоянием) на один слой обычного внимания с гейтом, и так дважды.
  • Gated Residual: четыре параллельных residual-потока вместо одного.
  • n-грамм-эмбеддинг после второго слоя: хеши 2- и 3-грамм в отдельные таблицы, 16.8M параметров считаем отдельно от основы.
  • Словарь 8 256 токенов: byte-level BPE для русского и английского, цифры по одной + управляющие токены.
  • Точные вычисления, как в Q-164M: модель пишет <CALC>4821*37<EQ>, исполнитель вписывает 178377. Арифметика, даты, дни недели, единицы, сортировка, проценты, простые числа.

Чат в браузере

Чат на сайте теперь работает на N-Q-26M-Chat. Модель, токенизатор и исполнитель переписаны на обычный JavaScript: 47 МБ весов в формате QPACK2 (int8), вычисления в WebAssembly с SIMD — около 75 токенов в секунду, никакого сервера. Прогон в браузере сверен с PyTorch: логиты расходятся не больше чем на 2·10⁻⁵, жадная генерация совпадает токен в токен. Прошлый чат с Q-U-164M — на отдельной странице.

N-Q-26M-JEV: модель решений

Из того же чекпоинта сделали вариант в духе Jev: вместо текста он за один проход выдаёт выбор из вариантов, оценку по шкале или вероятность «да» с откалиброванными вероятностями. Хорошо работает на задачах, на которых обучен (сопоставление вопроса и ответа — 98–99%, тематика — 81–89%, токсичность и тональность — 78–80%); новые типы вопросов решает около случайного уровня. Демо в браузере, разбор, веса.

The architecture was chosen by an ablation

Instead of reaching for our ternary Q architecture by default, we trained three candidates of the same size on identical data (0.5B tokens, one schedule) and compared held-out loss:

CandidateLoss (EN / RU-edu / RU-wiki)Mean
A — the Q-164M design (ternary weights, frozen fingerprint vocabulary)2.92 / 3.29 / 2.983.06
B — mini Qwen3.8-Flash-Next2.52 / 2.83 / 2.502.62
C — B + ternary weights + fingerprint vocabulary0.2 behind B at every checkpoint, stopped early

B won by a wide margin and became the architecture of the whole ladder. At this size, ternary weights cost too much quality.

Architecture

  • 8 layers: three Gated DeltaNet layers (linear attention with a recurrent state) per one gated full-attention layer, twice.
  • Gated Residual: four parallel residual streams instead of one.
  • n-gram embedding after layer 2: 2- and 3-gram hashes into separate tables; its 16.8M parameters are counted apart from the backbone.
  • An 8,256-token vocabulary: byte-level BPE for Russian and English, digits one per token, plus control tokens.
  • Exact computation, as in Q-164M: the model writes <CALC>4821*37<EQ> and the executor fills in 178377. Arithmetic, dates, weekdays, units, sorting, percentages, primes.

Chat in the browser

The site chat now runs N-Q-26M-Chat. The model, tokenizer and executor were rewritten in plain JavaScript: 47 MB of weights in QPACK2 format (int8), computed in WebAssembly with SIMD — about 75 tokens/s, no server. The in-browser forward pass is checked against PyTorch: logits within 2·10⁻⁵, greedy generation identical token for token. The previous Q-U-164M chat is on its own page.

N-Q-26M-JEV: a decision model

From the same checkpoint we made a Jev-style variant: instead of text it returns, in one forward pass, a choice among options, a level on a scale or a probability of "yes", with calibrated probabilities. It is good at the tasks it was trained on (question–answer matching 98–99%, topics 81–89%, toxicity and sentiment 78–80%); new kinds of questions it answers near chance. Demo in the browser, writeup, weights.

What's next

N-Q-26M is the smallest model of the ladder. N-Q-164M (8B tokens) is training now, followed by 64M and an MoE variant. More updates soon.

架构由消融实验选出

我们没有直接采用自己的三元 Q 架构，而是在相同数据（5 亿词元、同一训练计划）上训练了三个同等规模的候选，并比较留出数据上的 loss：

候选Loss（EN / RU-edu / RU-wiki）平均
A —— Q-164M 设计（三元权重、冻结指纹词表）2.92 / 3.29 / 2.983.06
B —— 迷你版 Qwen3.8-Flash-Next2.52 / 2.83 / 2.502.62
C —— B + 三元权重 + 指纹词表每个检查点都落后 B 0.2，提前停止

B 以明显优势胜出，成为整个系列的架构。在这个规模上，三元权重对质量的代价太大。

架构

  • 8 层：每三层 Gated DeltaNet（带循环状态的线性注意力）配一层带门控的全注意力，重复两次。
  • Gated Residual：四条并行的残差流，而不是一条。
  • 第 2 层之后的 n-gram 嵌入：2-gram 和 3-gram 的哈希映射到独立的表中，其 16.8M 参数与主干分开统计。
  • 8,256 词元的词表：面向俄语和英语的字节级 BPE，数字逐个切分，另有控制词元。
  • 与 Q-164M 相同的精确计算：模型写出 <CALC>4821*37<EQ>，执行器填入 178377。支持算术、日期、星期、单位换算、排序、百分比、质数。

浏览器中的聊天

网站聊天现在运行的是 N-Q-26M-Chat。模型、分词器和执行器都用普通 JavaScript 重写：QPACK2 格式（int8）的 47 MB 权重，在带 SIMD 的 WebAssembly 中计算 —— 每秒约 75 个词元，不需要服务器。浏览器中的前向计算已与 PyTorch 对齐：logits 误差在 2·10⁻⁵ 以内，贪心生成逐词元一致。之前的 Q-U-164M 聊天在单独的页面。

N-Q-26M-JEV：决策模型

我们用同一个检查点做了一个类似 Jev 的版本：它不生成文本，而是一次前向计算给出选项中的选择、量表上的等级或"是"的概率，概率经过校准。在训练过的任务上表现良好（问答匹配 98–99%、主题 81–89%、毒性和情感 78–80%）；新类型的问题则接近随机。浏览器演示、详细介绍、权重。

接下来

N-Q-26M 是这个系列中最小的模型。N-Q-164M（80 亿词元）正在训练，之后是 64M 和 MoE 版本。后续会有更新。
