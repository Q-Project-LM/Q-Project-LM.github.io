Модель на 53M параметров с тернарными весами, декодируется нативно из своего 33 МБ файла model.qpack — без сервера, без Python. Работает на скомпилированном ядре WebAssembly + SIMD (~30 ток/с, один поток), с запасным вариантом на чистом JavaScript.

A 53M-parameter ternary-weight model, decoded natively from its 33 MB model.qpack file — no server, no Python. Runs on a compiled WebAssembly + SIMD kernel (~30 tok/s, single-threaded), with a plain-JavaScript fallback.

一个 5300 万参数的三元权重模型，直接从 33 MB 的 model.qpack 文件原生解码 — 不需要服务器，不需要 Python。运行在编译好的 WebAssembly + SIMD 内核上（约 30 词元/秒，单线程），并带有纯 JavaScript 的备用方案。

При включённом Ask декодирование принудительно жадное (температура отключена) — именно так измерялась опубликованная цифра 98.7%; сэмплирование делает выбор circuit гораздо менее надёжным. Попробуй: 347 times 86? · 15% of 240? · Is 97 prime? · Sort 5, 2, 9. Модель сама пишет вычисление; детерминированный вычислитель (портирован из circuits.py, тот же код, что и в статье) заменяет цифры точным ответом. На необычных формулировках модель всё ещё может выбрать не тот circuit — это реальный режим отказа, честно описанный в статье.

With Ask on, decoding is forced greedy (temperature is disabled) — that's what the published 98.7% figure was measured with; sampling made circuit dispatch much less reliable. Try: 347 times 86? · 15% of 240? · Is 97 prime? · Sort 5, 2, 9. The model writes the calculation itself; a deterministic evaluator (ported from circuits.py, exact same code as the paper's) overwrites the digits with the exact answer. Unusual phrasings can still make the model pick the wrong circuit; that failure mode is real and disclosed in the write-up.

开启 Ask 后，解码被强制为贪心模式（温度被禁用）— 已发布的 98.7% 数据就是在这种设置下测得的；采样会让 circuit 的调用可靠性大幅下降。可以试试：347 times 86? · 15% of 240? · Is 97 prime? · Sort 5, 2, 9. 模型自己写出计算式；一个确定性求值器（从 circuits.py 移植而来，与论文中完全相同的代码）会用精确答案覆盖这些数字。遇到不常见的表述时，模型仍可能选错 circuit —— 这是真实存在的失败模式，在文章中如实说明。
